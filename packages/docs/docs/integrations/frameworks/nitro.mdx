# Nitro

`@kitajs/nitro-html-plugin` scans `server/pages` and registers each Kita JSX page as a
lazy Nitro v3 route. A root catch-all page becomes Nitro's lowest-priority renderer.

## Setup

:::danger XSS protection required

You must set up [`kita-html check`](/guide/xss/cli-scanner) from `@kitajs/html-cli` before
using this plugin to avoid XSS vulnerabilities. See the
[Getting started](/guide/getting-started) guide for complete setup instructions including
TypeScript configuration and XSS detection.

:::

Register the build-time module:

```ts title="nitro.config.ts"
import { defineConfig } from 'nitro'
import { nitroKitaHtml } from '@kitajs/nitro-html-plugin'

export default defineConfig({
  serverDir: './server',
  modules: [nitroKitaHtml()]
})
```

Create a default page:

```tsx title="server/pages/index.tsx"
export default function Home() {
  return (
    <html>
      <body>
        <h1>Home</h1>
      </body>
    </html>
  )
}
```

Pages default-export `(event: H3Event) => JSX.Element`. The event provides URL data, route
parameters, middleware context, and prepared response status and headers.

## Page Routes

The scanner supports `.tsx` and `.jsx` pages:

| File                  | Route            |
| --------------------- | ---------------- |
| `index.tsx`           | `/`              |
| `about.tsx`           | `/about`         |
| `blog/[slug].tsx`     | `/blog/:slug`    |
| `(admin)/users.tsx`   | `/users`         |
| `files/[...path].tsx` | `/files/**:path` |

Files and directories beginning with `_`, test files, and declaration files are ignored.
Equivalent routes are rejected at build time, including routes that differ only by a
dynamic parameter name or route group.

Each page receives its own virtual lazy handler for GET and HEAD. HEAD requests render the
page once to apply its status and headers, then return an empty body. Nitro route rules,
middleware, and prerendering continue to apply. Explicit API and route handlers have
priority over the renderer.

Restart `nitro dev` after adding or deleting page files. Existing page files continue to
rebuild normally when edited.

## Catch-All Renderer

Add one page that resolves to the root catch-all, such as `[...].tsx`, `[...name].tsx`, or
`(site)/[...].tsx`, to handle unmatched routes. More than one is rejected at build time:

```tsx title="server/pages/[...].tsx"
import { escapeHtml } from '@kitajs/html'
import type { H3Event } from 'nitro'

export default function App(event: H3Event) {
  return (
    <html>
      <body>
        <h1>{escapeHtml(event.url.pathname)}</h1>
      </body>
    </html>
  )
}
```

The renderer accepts GET and HEAD and preserves status 200 unless the page changes it. Set
`event.res.status = 404` when it acts as a not-found page. Other methods receive 405. A
named root catch-all does not create a stable route parameter; read the unmatched path
from `event.url.pathname`.

Convention pages use the factory-safe H3 adapter and always stream. `AutoSuspense` works
without additional options, including boundaries created after an asynchronous page
yields. Suspense currently requires a Node-compatible Nitro preset.
