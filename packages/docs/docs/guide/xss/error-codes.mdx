# Error codes

## TS88601 <Badge text="Error" type="danger" />

**Content may introduce an XSS vulnerability and must be marked with the `safe`
attribute.**

<br />

An expression with type `string` or `any` is used as a child of a native element without
the `safe` attribute.

```tsx twoslash kita
//@errors: 88601
let username = 'Arthur'
// ---cut---
const html = <div>{username}</div>
```

Variables prefixed with `safe` are exempt from this rule, as are expressions with safe
types _(numbers, booleans, string literals...)_.

::: tip Fix

Add the `safe` attribute to escape the content:

```tsx twoslash kita
//@errors: 88601
let username: string = 'Arthur'
// ---cut---
const html = <div safe>{username}</div>
```

:::

## TS88602 <Badge text="Error" type="danger" />

**The `safe` attribute causes this content to be escaped more than once.**

<br />

The `safe` attribute is applied to an element whose children include JSX elements. This
would escape the HTML output of those child components, corrupting their markup.

```tsx twoslash kita
//@errors: 88602
const user = { name: 'Arthur', badgeUrl: 'https://example.com/badge.png' }
function UserBadge(props: { url: string }) {
  return (
    <div class="badge">
      <img src={props.url} alt="User badge" />
    </div>
  )
}
// ---cut---
const html = (
  <div safe>
    {user.name}
    <UserBadge url={user.badgeUrl} />
  </div>
)
```

::: tip Fix

Remove `safe` from the parent and wrap only the untrusted text in `<Fragment safe>`, which
escapes it without adding a wrapper element:

```tsx twoslash kita
//@errors: 88602
const user = { name: 'Arthur', badgeUrl: 'https://example.com/badge.png' }
function UserBadge(props: { url: string }) {
  return (
    <div class="badge">
      <img src={props.url} alt="User badge" />
    </div>
  )
}
// ---cut---
import { Fragment } from '@kitajs/html'

const html = (
  <div>
    <Fragment safe>{user.name}</Fragment>
    <UserBadge url={user.badgeUrl} />
  </div>
)
```

:::

## TS88603 <Badge text="Error" type="danger" />

**Content inside a Component must be escaped using escapeHtml().**

<br />

An expression with type `string` or `any` is passed as a child to a component (uppercase
tag name). Unlike native elements, components cannot use the `safe` attribute directly on
children.

```tsx twoslash kita
//@errors: 88603
let userName: string = 'Arthur'
function Card({ children }: { children: JSX.Element }) {
  return <div>{children}</div>
}
// ---cut---
const html = <Card>{userName}</Card>
```

::: tip Fix

Escape manually using `escapeHtml()`:

```tsx twoslash kita
//@errors: 88603
import { escapeHtml } from '@kitajs/html'

let userName: string = 'Arthur'
function Card({ children }: { children: JSX.Element }) {
  return <div>{children}</div>
}
// ---cut---
const html = <Card>{escapeHtml(userName)}</Card>
```

Or wrap the content in a Fragment with `safe`:

```tsx twoslash kita
//@errors: 88603
import { Fragment } from '@kitajs/html'

let userName: string = 'Arthur'
function Card({ children }: { children: JSX.Element }) {
  return <div>{children}</div>
}

// ---cut---
const html = (
  <Card>
    <Fragment safe>{userName}</Fragment>
  </Card>
)
```

:::

## TS88604 <Badge text="Warning" type="warning" />

**The `safe` attribute is unused in this context.**

<br />

The `safe` attribute is applied to an element whose children are all already safe types
(numbers, booleans, bigints, string literals, or `JSX.Element`). These types cannot
introduce XSS, so the escaping is redundant. When at least one child needs escaping, as in
`<p safe>{name}{count}</p>`, the attribute is in use and `kita-html check` reports
nothing.

```tsx twoslash kita
//@errors: 88604
const count = 42
// ---cut---
const html = <span safe>{count}</span>
```

::: tip Fix

Remove the `safe` attribute, since numbers are already safe:

```tsx twoslash kita
//@errors: 88604
const count = 42
// ---cut---
const html = <span>{count}</span>
```

:::
